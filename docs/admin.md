# 管理者向けガイド

[← 最初のページに戻る](../README.md)

ツールそのものを管理する人向けです。当日の係の人は読まなくて大丈夫です。

団体で初めて使うときは、先に[団体で使い始めるとき](org-setup.md)を行ってください。このページは、そのあとの管理（直す・作り直す・ボタンを変える）の説明です。

Firebase と GitHub は画面のデザインがよく変わります。メニューの名前が少し違っていたら、近い名前のものを探してください。

## 全体のしくみ

```
操作用のPC ──┐                       ┌── 表示用のPC
             ├─→ Firebase（Googleの ─┤
             │    データ置き場）      │
kanpe.html は GitHub Pages が配っている（＝ツールのURL）
```

- **GitHub**：`kanpe.html` を置いて、URLで開けるようにしている
- **Firebase Realtime Database**：2台の間でメッセージを受け渡している。無料プラン（Spark）で足ります
- `kanpe.html` の中に、Firebaseの接続先（`databaseURL`）が1行だけ書いてあります

管理するものは「GitHubのリポジトリ」と「Firebaseのプロジェクト」の2つです。**どちらも、団体の複数人が入れる状態にしておいてください。** 作った本人しか入れないと、その人が抜けたときに直せなくなります。

## 1. Firebaseのルールを開ける

画面に「Firebaseに拒否されました(ルールを確認)」と出るときの直し方です。

一度下のルールを入れてあれば期限はないので、ふだんこの作業はいりません。必要になるのは、誰かがルールを閉じたときと、Firebaseを「テストモード」で作ってしまったときです。テストモードは**30日後に自動で読み書きが禁止されます**。

1. [Firebaseコンソール](https://console.firebase.google.com/)を開き、プロジェクトを作ったGoogleアカウントでログインする
2. このツール用のプロジェクトを選ぶ
3. 左のメニューから「Realtime Database」を開く（「構築」の中にあります）
4. 上のタブの「ルール」を押す
5. 書いてある内容を全部消して、下をそのまま貼る

   ```json
   {
     "rules": {
       "rooms": {
         "$room": {
           ".read": true,
           ".write": true
         }
       }
     }
   }
   ```

6. 「公開」を押す
7. [イベント前の準備の「動くかどうか確かめる」](setup.md#1-動くかどうか確かめる一番大事)で確認する

このルールには期限がないので、期限切れは起きません。

### このルールの意味と注意

- ルーム名を知っている人は、そのルームを読み書きできます。ルーム名が合言葉の役目をします
- ルームの一覧は誰にも見えません。だから、当てにくいルーム名にしておけば、他人に割り込まれにくくなります
- 流れるのは「残り3分」のような合図だけです。**個人情報や秘密は送らないでください**
- 長く使わない期間は、`true` を2か所とも `false` に変えて「公開」すれば完全に閉じられます。使う前に `true` へ戻します

## 4. ボタンを変える

1. GitHubで `kanpe.html` を開き、右上の鉛筆マーク（Edit）を押す
2. `data-text` で検索すると、ボタンが1行ずつ並んでいます

   ```html
   <button style="background:#4a86e8" data-color="#4a86e8" data-text="残り5分">残り5分</button>
   ```

3. 変えたい行を書き換える、または1行コピーして増やす

   | 場所 | 意味 |
   |---|---|
   | `data-text="残り5分"` | 足元の画面に出る文字 |
   | `>残り5分<` | ボタンに書いてある文字（普通は上と同じにする） |
   | `background:#4a86e8` | ボタンの色 |
   | `data-color="#4a86e8"` | 足元の画面の背景色（普通はボタンの色と同じにする） |
   | `data-blink="1"` を足す | 押すと点滅で表示される |

   色は `#` に続く6文字で指定します。「カラーコード」で検索すると選べます。白い文字が読める、濃い色にしてください。

4. 「Commit changes」を押す。1〜2分で反映されます
5. ツールのURLを再読み込みして、ボタンが変わったことと、押して足元に出ることを確認する

**本番の直前には変えないでください。** 記号を1つ消しただけで全体が動かなくなることがあります。おかしくなったら、GitHubの「History」から前の状態に戻せます。

---

## 5. イベントが終わったら

何もしなくても問題ありません。気になる場合：

- Firebaseコンソールの「Realtime Database」→「データ」で `rooms` を削除すると、残っているメッセージが消えます
- 次のイベントでは新しいルーム名を使います
