# 管理者向けガイド

[← 最初のページに戻る](../README.md)

ツールそのものを管理する人向けです。当日の係の人は読まなくて大丈夫です。

このページの手順には Firebase と GitHub の画面のスクリーンショットがありません。どちらも画面のデザインがよく変わるので、メニューの名前が少し違っていたら、近い名前のものを探してください。

## 全体のしくみ

```
操作用のPC ──┐                       ┌── 表示用のPC
             ├─→ Firebase（Googleの ─┤
             │    データ置き場）      │
kanpe.html は GitHub Pages が配っている（＝ツールのURL）
```

- **GitHub**：`kanpe.html` を置いて、URLで開けるようにしている
- **Firebase Realtime Database**：2台の間でメッセージを受け渡している。無料プラン（Spark）で足ります
- `kanpe.html` の中に、Firebaseの接続先（`databaseURL`）が1行だけ書いてあります

管理するものは「GitHubのリポジトリ」と「Firebaseのプロジェクト」の2つです。**どちらも、団体の複数人が入れる状態にしておいてください。** 作った本人しか入れないと、その人が抜けたときに直せなくなります。

---

## 1. Firebaseのルールを開ける

画面に「Firebaseに拒否されました(ルールを確認)」と出るときの直し方です。

Firebaseを「テストモード」で作ると、**30日後に自動で読み書きが禁止されます**。久しぶりに使うと動かない原因は、ほぼこれです。

1. [Firebaseコンソール](https://console.firebase.google.com/)を開き、プロジェクトを作ったGoogleアカウントでログインする
2. プロジェクト（現在は `tedxutsukubakanpe`）を選ぶ
3. 左のメニューから「Realtime Database」を開く（「構築」の中にあります）
4. 上のタブの「ルール」を押す
5. 書いてある内容を全部消して、下をそのまま貼る

   ```json
   {
     "rules": {
       "rooms": {
         "$room": {
           ".read": true,
           ".write": true
         }
       }
     }
   }
   ```

6. 「公開」を押す
7. [イベント前の準備の「動くかどうか確かめる」](setup.md#1-動くかどうか確かめる一番大事)で確認する

このルールには期限がないので、次から期限切れは起きません。

### このルールの意味と注意

- ルーム名を知っている人は、そのルームを読み書きできます。ルーム名が合言葉の役目をします
- ルームの一覧は誰にも見えません。だから、当てにくいルーム名にしておけば、他人に割り込まれにくくなります
- 流れるのは「残り3分」のような合図だけです。**個人情報や秘密は送らないでください**
- 長く使わない期間は、`true` を2か所とも `false` に変えて「公開」すれば完全に閉じられます。使う前に `true` へ戻します

## 2. Firebaseを新しく作る

今のFirebaseに入れる人がいない、団体のアカウントで作り直したい、というときの手順です。

1. 団体で共有しているGoogleアカウントで[Firebaseコンソール](https://console.firebase.google.com/)を開く
2. 「プロジェクトを作成」を押し、名前を付ける（例：`kanpe-団体名`）。Googleアナリティクスは「無効」でかまいません
3. 左のメニューから「Realtime Database」を開き、「データベースを作成」を押す
   - **Firestore ではありません。** 名前が似ているので注意
4. ロケーションは「シンガポール (asia-southeast1)」を選ぶ（日本から一番近い選択肢）
5. セキュリティルールはどちらを選んでもよい。作成後に[上の「ルールを開ける」](#1-firebaseのルールを開ける)の5〜6を行う
6. 「データ」タブの上のほうに出ているURLをコピーする。こういう形です

   ```
   https://プロジェクト名-default-rtdb.asia-southeast1.firebasedatabase.app
   ```

7. GitHubで `kanpe.html` を開き、右上の鉛筆マーク（Edit）を押す
8. `databaseURL` と書いてある行を探し（`Ctrl + F` で検索）、`" "` の中身をコピーしたURLに置き換える

   ```javascript
   const firebaseConfig = {
     databaseURL: "ここに貼る"
   };
   ```

9. 右上の「Commit changes」を押す。1〜2分でツールのURLに反映されます
10. 動作確認をする

### ほかの人も入れるようにする

Firebaseコンソール左上の歯車 →「ユーザーと権限」→「メンバーを追加」で、団体のメンバーを「オーナー」として2人以上入れておきます。

## 3. 団体のGitHubにコピーを作る

元のリポジトリは個人のアカウント（`tmdmy/tedx_roder`）にあります。これを団体のGitHub（Organization）に**コピー**して、団体はそのコピーを使います。元のリポジトリはそのまま残ります。

この作業は**団体側の人**が行います。GitHubの「Fork（フォーク）」という機能を使います。ボタンを押すだけで、履歴ごとコピーできます。

**準備**：作業する人が、団体のOrganizationでリポジトリを作れる権限を持っていること。

### コピーを作る

1. GitHubにログインして、[元のリポジトリ](https://github.com/tmdmy/tedx_roder)を開く
2. 右上の「Fork」を押す
3. 「Owner」で**団体のOrganization名**を選ぶ（自分の名前のままにしない）
4. 「Repository name」はそのままでも、変えてもよい（例：`kanpe`）。ここで決めた名前がURLの一部になります
5. 「Create fork」を押す。団体のGitHubにコピーができます

### URLで開けるようにする（GitHub Pages）

コピーしただけでは、まだツールのURLがありません。

1. コピーしたリポジトリで、上の「Settings」→ 左の「Pages」を開く
2. 「Branch」で `main` を選び、フォルダは `/ (root)` のまま「Save」を押す
3. 数分待ってページを再読み込みすると、上のほうに新しいURLが出ます。ツールのURLはこの形になります

   ```
   https://団体のOrganization名.github.io/リポジトリ名/kanpe.html
   ```

4. そのURLを開いて、モード選択の画面が出ることを確認する

### 説明書のURLを書き換える

コピーした説明書には、元のURL（`tmdmy.github.io/...`）が書かれたままです。団体のURLに直します。

1. コピーしたリポジトリで `README.md` を開き、右上の鉛筆マーク（Edit）を押す
2. 「このツールのURL」の下のURLを、新しいURLに書き換える
3. その下の「元のリポジトリは…」で始まる注意書きの1行は消してよい
4. 「Commit changes」を押す
5. [イベント前の準備の「動くかどうか確かめる」](setup.md#1-動くかどうか確かめる一番大事)を、新しいURLで行う

### 注意

- **これ以降、団体の人は団体のURLだけを使ってください。** 元のURL（`tmdmy.github.io/...`）は個人のものなので、いつか消えるかもしれません
- Firebaseは同じものを共有します。コピーしてもそのまま動きます。ただし[団体の人が入れる状態](#ほかの人も入れるようにする)にしておくか、[団体用に作り直して](#2-firebaseを新しく作る)ください
- 元のリポジトリが更新されたとき、コピー側のリポジトリの上に出る「Sync fork」→「Update branch」を押すと、更新を取り込めます。自分たちで `README.md` や `kanpe.html` を書き換えた箇所とぶつかった場合は、取り込まずにそのままでかまいません

## 4. ボタンを変える

1. GitHubで `kanpe.html` を開き、右上の鉛筆マーク（Edit）を押す
2. `data-text` で検索すると、ボタンが1行ずつ並んでいます

   ```html
   <button style="background:#4a86e8" data-color="#4a86e8" data-text="残り5分">残り5分</button>
   ```

3. 変えたい行を書き換える、または1行コピーして増やす

   | 場所 | 意味 |
   |---|---|
   | `data-text="残り5分"` | 足元の画面に出る文字 |
   | `>残り5分<` | ボタンに書いてある文字（普通は上と同じにする） |
   | `background:#4a86e8` | ボタンの色 |
   | `data-color="#4a86e8"` | 足元の画面の背景色（普通はボタンの色と同じにする） |
   | `data-blink="1"` を足す | 押すと点滅で表示される |

   色は `#` に続く6文字で指定します。「カラーコード」で検索すると選べます。白い文字が読める、濃い色にしてください。

4. 「Commit changes」を押す。1〜2分で反映されます
5. ツールのURLを再読み込みして、ボタンが変わったことと、押して足元に出ることを確認する

**本番の直前には変えないでください。** 記号を1つ消しただけで全体が動かなくなることがあります。おかしくなったら、GitHubの「History」から前の状態に戻せます。

---

## 5. イベントが終わったら

何もしなくても問題ありません。気になる場合：

- Firebaseコンソールの「Realtime Database」→「データ」で `rooms` を削除すると、残っているメッセージが消えます
- 次のイベントでは新しいルーム名を使います
